Section 1 • ~30% of Exam

Fundamentals of Generative AI

Core AI/ML/DL hierarchy, foundation model mechanics, C-S-D-A business value archetypes, learning paradigms, data readiness, and the 4-stage ML lifecycle.

Concentric AI Hierarchy

AI (broadest human-like machine intelligence) → ML (learning patterns from data without explicit rules) → Deep Learning (multi-layer neural networks) → Foundation Models (pre-trained on massive unlabeled data, adaptable to many tasks) → Generative AI (creates new text, code, images, audio, video).

Four Primary Gen AI Use Archetypes (C-S-D-A)

Create (draft customer replies via Conversational AI, client emails in Gmail, presentation visuals in Slides, marketing design concepts in Nano Banana, troubleshooting videos in Google Vids, unit tests & starter code in Gemini Code Assist) • Summarize (financial reports in Gemini Notebook Enterprise, customer sentiment in Looker, meeting action items in Meet, complex data visuals/graphs in Gemini in BigQuery) • Discover (demand forecasting & molecular fine-tuning on Agent Platform, churn-reducing recommendations in Agent Search, Drive file Q&A, cross-silo search in Gemini Enterprise, real-time fraud anomaly detection) • Automate (accessible format conversion via Speech/Translation APIs, contract extraction in Document AI, automated code docs via Gemini Code Assist [legacy exam name: Codey], automated ticket routing).

Three ML Learning Paradigms

Supervised Learning = labeled data (input-output targets known—including unstructured free-text customer emails manually tagged 'Billing' or 'Tech Support'). Unsupervised Learning = unlabeled data (discovers natural clusters, segments, or anomalies). Reinforcement Learning = agent/robot learns optimal actions via numeric rewards & penalties through environment interaction (heavily tested, including RLHF used to align LLMs).

Data Readiness & 4-Stage ML Lifecycle

Structured data (SQL/tabular rows) vs. Unstructured data (PDFs, audio, video, emails — ~80%+ of org data). Requires Quality Data (accurate, complete, consistent, relevant) + Accessible Data. Lifecycle: 1. Data Ingestion & Prep → 2. Model Training → 3. Model Deployment → 4. Model Management (Registry versioning + Drift Monitoring).

Model Ecosystem Spectrum

4-Category Model Catalog: (1) First-Party Foundation Models — Gemini (Pro, Flash, Flash-Lite, Nano), Gemini Flash Image (Nano Banana 2), Veo 3.1 (text/image-to-video), Lyria (audio/music), Chirp 3 (speech-to-text), Embeddings; (2) First-Party Pre-Trained APIs — Speech-to-Text, Natural Language, Translation/Document Translation, Vision, Video Intelligence, Document AI; (3) Open Models — Gemma 2/3/3n/4, CodeGemma, PaliGemma, ShieldGemma 2, Meta Llama 3.1/3.2, Mistral, AI21, TII Falcon, BERT, FLAN-T5, ViT, EfficientNet; (4) Third-Party Partner Models in Model Garden — Anthropic Claude model family.

Exam Watchout: Do not confuse Predictive/Discriminative ML (forecasting numbers, counting visitors, classifying spam) with Generative AI (creating novel text, code, images, audio, or synthetic summaries)—and remember Veo generates video from static text/images, NOT live fluctuating real-time telemetry dashboards.
Section 2 • ~35% of Exam (Highest Weight)

Google Cloud's Generative AI Offerings

Matching organizational problems to the 5-layer Google Cloud AI stack: Infrastructure, Models, Agent/Vertex Platform, Agents, Pre-trained APIs, and Workspace/Enterprise apps.

5-Layer Google Cloud Gen AI Stack

1. Infrastructure (GPUs, custom TPUs, LiteRT edge) → 2. Models (First-party, Open, Third-party in Model Garden; custom via AutoML / Model Builder) → 3. Platform (Vertex AI / Gemini Enterprise Agent Platform MLOps) → 4. Agents (Model + Reasoning Loop + Tools) → 5. End-User Apps (Workspace, Gemini Enterprise, CX Suite).

Anatomy & Taxonomy of AI Agents

Every Gen AI Agent combines 3 core parts: 1. Foundation Model ('brain'), 2. Reasoning Loop (observe → interpret → reason → act), and 3. Tools (Extensions for external APIs, Functions for defined actions, Data Stores for RAG knowledge, Plugins). Control styles: Deterministic, Generative, Hybrid, and Multi-Agent Systems. Functional role archetypes: Conversational agent (natural dialogue / VR), Code agent (write/review/debug software), Workflow agent, Data agent, and Creative agent.

Section 3 • ~20% of Exam

Techniques to Improve Gen AI Model Output

Overcoming knowledge cutoffs, hallucinations, and bias using the cost-aware escalation ladder: Prompting → Grounding → RAG → Fine-Tuning → HITL.

Six Foundation Model Limitations

1. Knowledge Cutoff (frozen at training date) • 2. Hallucinations (plausible fabrications) • 3. Data Dependency & Bias (amplifies training corpus flaws) • 4. No Private Enterprise Context • 5. Finite Context Window (token ceiling) • 6. Edge Cases (rare/atypical inputs).

RAG vs. Fine-Tuning vs. Grounding (Canonical Distinction)

Grounding is the overarching goal of connecting model outputs to verifiable sources. RAG (Retrieve → Add to prompt → Generate) is a primary grounding technique powered by Semantic Search (matching conceptual meaning and user intent via dense vector embeddings rather than brittle exact keywords) and Vector Databases / Data Stores—updating facts dynamically without retraining weights. Fine-Tuning trains a pre-trained model on curated task/domain-specific datasets to adapt style, nomenclature, or domain grounding behavior.

Prompt Engineering Toolkit

Workspace P-T-C-F Framework (Persona + Task [mandatory action verb] + Context [@file grounding] + Format, ~21+ words + iterative follow-ups) • Zero-shot (0 examples), One-shot (1 example), Few-shot (multiple examples enforcing format/pattern) • Role Prompting • Prompt Chaining • Chain-of-Thought / CoT • ReAct (Reason + Act with tools) • Metaprompting (using AI to write/refine system prompts).

Sampling & Run Parameters

System Instructions define agent context, persona, and rules BEFORE user input across 4 goals: Consistency (tone/persona), Accuracy (domain grounding & admitting uncertainty), Relevance (staying in scope + handoff rules), and Safety (blocking unhelpful/unsafe replies; graduate to CX Agent Studio for enterprise adversarial defense) • Temperature: Low (0.0–0.2) = formal, deterministic, factual; High (0.7–1.0) = passionate, creative variety • Top-P: cumulative probability focus vs. elaboration • Output Length: token/word ceiling.

Human-in-the-Loop (HITL) & Explainable AI Governance

Mandatory human expert oversight in high-risk workflows (healthcare, HR, finance, legal, moderation) via Pre-generation review and Post-generation review. Pair with Explainable Gen AI policies when stakeholders require decision transparency ('why an output ranked or excluded an individual'), distinct from Fairness assessments (auditing group bias).

Exam Watchout: Never pick Fine-Tuning when a company's primary need is answering questions from frequently updated manuals, inventory, or policies while minimizing hallucinations — that is ALWAYS Grounding / RAG.
Section 4 • ~15% of Exam

Business Strategies for a Successful Gen AI Solution

Pre-project scoping (6 Needs + 3 Resources), multi-directional change management, KPI measurement, and Google's Secure AI Framework (SAIF).

Pre-Project Scoping: 6 Needs & 3 Resources

6 Needs: Scale, Customization, User Interaction, Privacy, Latency, and Connectivity (cloud vs. offline edge). 3 Resources: People (in-house ML skill), Money (budget/TCO), and Time (speed-to-market). Google Cloud's Open Approach prevents single-vendor lock-in across diverse tools, while Google Cloud democratizes AI for teams lacking ML specialists via low-code/no-code AutoML, Model Garden pre-trained models, and easy-to-use APIs (always retaining Human-in-the-Loop—never 'zero human input').

Multi-Directional Adoption (Top-Down + Bottom-Up)

Combine Top-Down executive sponsorship (vision, Responsible AI guardrails, data strategy, KPIs) with Bottom-Up employee experimentation (frontline teams identifying real friction points and sharing reusable prompts).

Six Pillars of Gen AI Execution & ROI

1. Strategic Focus (start with high-impact, feasible use cases) • 2. Exploration (safe sandboxes) • 3. Responsible AI • 4. Resourcing (data quality + upskilling) • 5. Impact Measurement (define baseline metrics FIRST, collect data, iterate) • 6. Continuous Improvement (monitor drift via Model Monitoring).

Secure AI Framework (SAIF) & Cloud Security

SAIF mitigates AI-specific risks (prompt injection, data poisoning, model theft, sensitive data leakage). Enforced on Google Cloud via Identity and Access Management (IAM least privilege), Security Command Center (posture visibility), SynthID watermarking, and Google Cloud's enterprise privacy commitment (customer data/prompts are NOT used to train public foundation models).

Trust Through Transparency, Sovereignty & FinOps

Google Cloud Transparency commitments ensure customer data and prompts remain customer-owned and are never used to train public foundation models without permission, backed by Access Transparency logs, regional Data Residency / Sovereignty selection, Carbon-Free Energy (CFE%) region placement, and 3-way Quality vs. Latency vs. Cost FinOps governance.

Exam Watchout: Avoid 'all-at-once' enterprise rollouts or skipping governance for speed. The exam rewards starting with focused, measurable pilot use cases backed by clear baseline KPIs, SAIF security, and Top-Down + Bottom-Up alignment.

Metaprompting uses an AI model to generate, modify, or refine prompts/system instructions for another AI task or agent.
Question 11 of 25 • Section 3 • Improve Model Output

When configuring sampling parameters for a factual compliance Q&A assistant where consistency and minimal randomness are critical, how should Temperature be set?

Lower Temperature values make token selection more deterministic, factual, and consistent; higher values increase randomness and creative variety.

Question 14 of 25 • Section 3 • Improve Model Output

In Google Cloud's agent architecture, what distinguishes the ReAct (Reason + Act) framework from standalone Chain-of-Thought (CoT) prompting?

Instructor-annotated Module 5 formula: ReAct = CoT + Tools. The agent reasons step-by-step, acts by calling an Extension/Function/Data Store, observes the external result, and iterates until the goal is met.

Question 19 of 25 • Section 3 & 4 • Responsible AI & Transparency

A regional credit union pilots a Gen AI loan-triage assistant, but compliance officers object that loan underwriters cannot see why the system flagged or deprioritized specific applicant files. Which action directly addresses this lack of decision transparency?

Question 20 of 25 • Section 1 • Fundamentals

A logistics firm runs two AI initiatives: (1) an autonomous yard shuttle learns optimal docking maneuvers by earning positive points for smooth, on-time docks and point deductions for delays; and (2) an operations team trains a ticket router using 30,000 free-text customer emails that analysts manually tagged as 'Customs Hold', 'Damaged Freight', or 'Invoice Query'. Which pairing accurately classifies both?

Learning through trial-and-error interaction with numeric rewards and penalties is Reinforcement Learning. Even though free-text email prose is unstructured, manually attaching target category tags ('Customs Hold', etc.) makes the dataset Labeled Data suitable for supervised ML.

Google Cloud's open approach mitigates vendor lock-in across diverse tools and open/partner models, while AI democratization lowers technical barriers via AutoML, Model Garden, and easy-to-use APIs. Question 24 of 25 • Section 1 • Fundamentals

An energy utility director proposes using Google's Veo model as a live control-room display to continuously ingest and plot second-by-second smart-grid voltage fluctuations. Why is Veo inappropriate for this use case?

Veo creates high-definition video from static text prompts or still reference images; it cannot dynamically ingest and render live fluctuating telemetry streams (use BI/visualization tools such as Looker for live data, Nano Banana / Imagen for photorealistic images, and Chirp for speech-to-text).
