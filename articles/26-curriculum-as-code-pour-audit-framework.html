The POUR-Audit Framework in Curriculum-as-Code

Currículum como Código y el Marco de Auditoría POUR

Published: August 19, 2026 • Author: Alan Pruitt • POUR-Audit SSoT

Treating educational content as software—known as Curriculum-as-Code (CaC)—enables the integration of automated verification pipelines to enforce instructional quality, semantic hierarchy, and digital accessibility. The POUR-Audit framework operationalizes Web Content Accessibility Guidelines (WCAG) into testable, programmatically audited standards directly inside git workflows.

1. Perceivable: Asset Alt-Text Enforcement

Digital equity requires that all instructional media is perceivable. Programmatic scans analyze <img ...> tags in the course fleet:

  • Descriptive Text: Every image tag must contain a descriptive alt attribute.
  • Prohibited Placeholders: Empty placeholders (alt="" or alt='') are flagged as failures to prevent decorative bypass of active educational charts.

2. Operable: Navigation and Focus Flow Parity

Operable interfaces ensure that all students can navigate course layouts using keyboard controls and adaptive gear:

  • Focus Indicators: Audits verify that interactive elements within custom Canvas containers retain highly visible focus rings.
  • Focus Traps: Programmatic checks scan script bindings to ensure custom modal layers do not create keyboard focus traps.

3. Understandable: Legacy Term Deprecation

To maintain clear and accurate instructional pathways, the audit monitors prohibited legacy terms and references:

  • Legacy Patterns: References containing deprecated structural patterns (such as "8.#"-style module references) are checked and flagged.
  • Unified Terminology: Ensures course fleet documentation aligns with current academic sources of truth (SSoT).

4. Robust: Semantic Structure and Hierarchy

A robust curriculum is built on standard HTML5 landmarks that assistive technologies can parse reliably. The audit checks heading structures to confirm strict semantic progression:

  • Entry Constraints: The content body must start with a ## (H2) heading level. H1 is reserved exclusively for the Canvas LMS Page Title.
  • Structural Parity: Audits scan header trees programmatically, ensuring no skipped heading levels (e.g. from H2 to H4) exist, which disorients screen readers.

5. Case Study: The Fleet-Wide Refactor Edge Case

An illustrative edge case occurred during a repository-wide emoji refactor to meet ADA Title II requirements. An automated python script stripped all decorative emoticons from markdown headings, but left behind multiple spaces after ATX hashes (e.g., changing ## 🎯 Learning Objectives to ## Learning Objectives).

Because the pre-commit hook runs markdownlint, the commit was automatically rejected for MD019 (multiple space ATX heading violations). This highlights the necessity of coupling content transformation scripts with automated syntax gates before any assets reach the production LMS.

Tratar el contenido educativo como software, conocido como Currículum como Código (CaC), permite la integración de flujos de verificación automatizados para aplicar la calidad instruccional, la jerarquía semántica y la accesibilidad digital. El marco de auditoría POUR operacionaliza las Pautas de Accesibilidad para el Contenido Web (WCAG) en estándares probables y auditados mediante programación directamente dentro de los flujos de trabajo de git.

1. Percebible: Aplicación de Texto Alternativo para Recursos

La equidad digital requiere que todos los medios instruccionales sean percibidos. Los escaneos programáticos analizan las etiquetas <img ...> en el conjunto de cursos:

  • Texto descriptivo: Cada etiqueta de imagen debe contener un atributo alt descriptivo.
  • Marcadores de posición prohibidos: Los marcadores de posición vacíos (alt="" o alt='') se marcan como fallas para evitar la elusión decorativa de gráficos educativos activos.

2. Operable: Navegación y Paridad en el Flujo de Foco

Las interfaces operables garantizan que todos los estudiantes puedan navegar por los diseños de los cursos utilizando controles de teclado y dispositivos adaptativos:

  • Indicadores de foco: Las auditorías verifican que los elementos interactivos dentro de los contenedores personalizados de Canvas conserven anillos de foco altamente visibles.
  • Trampas de foco: Los controles programáticos escanean las vinculaciones de scripts para garantizar que las capas modales personalizadas no creen trampas de foco en el teclado.

3. Comprensible: Depreciación de Términos Heredados

Para mantener rutas de instrucción claras y precisas, la auditoría supervisa los términos y referencias heredados que están prohibidos:

  • Patrones heredados: Se verifican y marcan las referencias que contienen patrones estructurales obsoletos (como referencias de módulos al estilo "8.#").
  • Terminología unificada: Garantiza que la documentación del conjunto de cursos se alinee con las fuentes de verdad académicas actuales (SSoT).

4. Robusto: Estructura Semántica y Jerarquía

Un currículo robusto se construye sobre hitos estándar de HTML5 que las tecnologías de asistencia pueden analizar de manera confiable. La auditoría verifica las estructuras de encabezado para confirmar una progresión semántica estricta:

  • Restricciones de entrada: El cuerpo del contenido debe comenzar con un nivel de encabezado ## (H2). H1 está reservado exclusivamente para el Título de la Página de Canvas LMS.
  • Paridad estructural: Las auditorías escanean árboles de encabezados mediante programación, asegurando que no existan niveles de encabezado omitidos (por ejemplo, de H2 a H4), lo que desorienta a los lectores de pantalla.

5. Caso de Estudio: El Caso Borde del Refactor en Todo el Repositorio

Un caso de estudio ilustrativo ocurrió durante un refactor de emojis en todo el repositorio para cumplir con los requisitos del Título II de la ADA. Un script de python automatizado eliminó todos los emoticonos decorativos de los encabezados de markdown, pero dejó espacios múltiples después de los caracteres hash de ATX (por ejemplo, cambiando ## 🎯 Learning Objectives a ## Learning Objectives).

Debido a que el gancho de pre-commit ejecuta markdownlint, el commit fue rechazado automáticamente por violaciones MD019 (múltiples espacios en encabezados ATX). Esto resalta la necesidad de acoplar los scripts de transformación de contenido con puertas de sintaxis automatizadas antes de que cualquier recurso llegue al LMS de producción.
